# Food Logging — Test Plan

Тест-план для проверки всех основных сценариев записи еды через Telegram-бота
после серии фиксов 2026-05-11/12 (TZ-aware time, deterministic ack,
INBOUND audit, drop_pending_updates=False).

## Как пользоваться

Каждый кейс — три части: **что отправить боту**, **что ожидаем в ответе**,
**как проверить в DB / Railway logs**. Прогоняй сверху вниз, отмечай ✅/❌
в чек-листе внизу. После прогона: для упавших — копию ответа бота + DB-state
в обсуждение, я разберу.

Сценарии глюкозы (`/glucose`, `glucose_around_meal`, `/glucose_weekly`)
вынесены отдельным блоком — запускать только после того как в Railway logs
появится `Libre sync ok: wrote N readings`.

## P0 — Базовое логирование текстом

### T1. Простой текст без указания времени
- **Отправить:** `съела два яйца и тост с маслом`
- **Ответ бота:** в конце блок `✅ Записано:` с двумя строками, время = текущий час Amsterdam (±2 мин)
- **DB:** в `daily_logs` за сегодня добавлены 2 meal-записи с одинаковым `time` (текущий) и описаниями про яйца и тост

### T2. Поиск в базе рецептов (hit)
- **Отправить:** `съела протеиновый коктейль`
- **Ответ:** Coach сначала вызывает `lookup_recipe`, использует сохранённые данные (190 ккал, 25.7 г белка)
- **DB:** 1 meal, calories=190, protein=25.7. В `recipes` ничего нового не добавлено

### T3. Явное время в текущем сообщении
- **Отправить:** `в 19:00 ела курицу с гречкой`
- **Ответ:** в блоке `✅ Записано:` время `19:00`, **не** текущий час
- **DB:** meal.time = "19:00"

### T4. Относительное время
- **Отправить:** `час назад выпила кофе`
- **Ответ:** время ≈ (текущий час − 1):MM
- **DB:** meal.time близко к now − 60 мин (±5 мин)

### T5. Новое блюдо (lookup miss)
- **Отправить:** `съела авокадо-тост с лососем и яйцом-пашот` (предполагается что блюда нет в `recipes`)
- **Ответ:** Coach пробует `lookup_recipe`, не находит → оценивает макросы → вызывает `save_recipe` → залогирует
- **DB:** 1 новая meal + 1 новая строка в `recipes`

## P0 — Корректировки и чтение

### T6. Правка калорий последней записи
- **Сделать:** залогируй любое блюдо, потом отправь `там было не 200 а 300 ккал`
- **Ответ:** вызов `edit_food_log`, ack-блок про правку
- **DB:** последняя meal: calories=300, остальные поля без изменений

### T7. Правка описания
- **Сделать:** залогируй курицу, потом `это была не курица а индейка`
- **Ответ:** `edit_food_log` меняет description
- **DB:** последняя meal с новым описанием

### T8. Чтение лога дня
- **Отправить:** `что я ела сегодня?`
- **Ответ:** список всех meals + итоги (ккал, белок)
- **DB:** без изменений

### T9. /status команда
- **Отправить:** `/status`
- **Ответ:** сводка дня + остаток до таргета (1650 ккал, 143 г белка)
- **DB:** без изменений

## P1 — Фото и голос

### T10. Фото еды без подписи
- **Отправить:** фото тарелки
- **Ответ:** карточка распознанного с пометками 📚 (из базы) / ~ (оценка), внизу «Напиши `да` — залогирую»
- **DB:** без изменений (ждём подтверждения)

### T11. Подтверждение фото
- **Сделать:** после T10 написать `да`
- **Ответ:** блок `✅ Залогировано N позиций` + итоги дня
- **DB:** N meals добавлены с одинаковым `time` (момент подтверждения)

### T12. Правка карточки фото
- **Сделать:** после T10 написать `там было 3 яйца, не 2`
- **Ответ:** обновлённая карточка, **всё ещё ждёт подтверждения**
- **DB:** без изменений

### T13. Отмена фото
- **Сделать:** после T10 написать `отмена`
- **Ответ:** `Отменено, ничего не залогировано.`
- **DB:** без изменений

### T14. Голосовое сообщение
- **Отправить:** voice «съела пять клубничек»
- **Ответ:** сначала `🎤 _съела пять клубничек_`, потом обычная логика + ack-блок
- **DB:** 1 meal про клубнику

## P1 — Reliability (главное, ради чего весь день фиксили)

### T15. Audit log входящих сообщений
- **Где смотреть:** Railway → Deployments → Logs текущего деплоя
- **Что искать:** на каждое сообщение из T1–T14 должна быть строка вида
  `INBOUND text uid=126204551 role=coach msg_id=... len=N: '...'`
  (для фото — `INBOUND photo`, для голоса — `INBOUND voice` + второй `INBOUND voice ... transcript:`)
- **Ожидание:** для каждого отправленного сообщения ровно одна `INBOUND` строка с правильным `msg_id`

### T16. updated_at реальный
- **Где смотреть:** Supabase → Table Editor → `daily_logs` → строка за сегодня
- **Что:** колонка `updated_at` обновляется в пределах ~30 сек от каждого `log_*`
- **Раньше:** залипал на timestamp первого INSERT за день

### T17. Детерминированный ack
- **Где смотреть:** ответы бота во всех T1–T7
- **Что:** ровно в каждом ответе после log_food/edit_food_log/log_workout/log_sleep/log_weight есть блок
  `✅ Записано:` (или `✏️` для edit). Без этого блока — silent fail
- **Раньше:** надеялись на LLM, иногда забывал

### T18. drop_pending после рестарта
- **Сделать:** отправить сообщение → подождать 5 сек → в Railway сделать Redeploy → отправить ещё одно сообщение прямо во время билда → подождать пока бот поднимется
- **Ожидание:** оба сообщения обработаны (второе подхвачено после старта)
- **Раньше:** второе сообщение терялось

## P2 — Edge cases

### T19. Эмодзи и пунктуация
- **Отправить:** `🍕 пицца! где-то 200г`
- **Ответ:** залогировано без падений
- **DB:** meal с description, содержащим пиццу

### T20. Английский ввод
- **Отправить:** `had a banana for breakfast`
- **Ответ:** Coach распознаёт еду, логирует
- **DB:** meal про банан

### T21. Неопределённое сообщение
- **Отправить:** `что-то съела`
- **Ответ:** бот **не** логирует, спрашивает что именно
- **DB:** без изменений

### T22. Полночный roll-over
- **Сделать:** в 23:55 Amsterdam отправить `сейчас ем яблоко`, в 00:30 Amsterdam — `съела бутерброд`
- **Ожидание:** первое в `daily_logs` сегодняшней даты, второе — следующей
- **Раньше:** мог отвалиться из-за UTC roll-over раньше времени

## Глюкоза (запускать только после `Libre sync ok` в логах)

### G1. Текущая глюкоза
- **Отправить:** `какая сейчас глюкоза?`
- **Ответ:** число в ммоль/л + стрелка тренда + возраст показания в минутах

### G2. График за 12 часов
- **Отправить:** `/glucose`
- **Ответ:** PNG-график с маркерами еды поверх кривой + интерпретация (TIR%, пики)

### G3. Реакция на конкретный приём пищи
- **Сделать:** через ~1.5–2 часа после log_food отправить `как я отреагировала на завтрак?`
- **Ответ:** baseline, peak, delta, time-to-peak, return-to-baseline + комментарий по дельте

### G4. Недельный анализ
- **Отправить:** `/glucose_weekly` (или дождаться воскресенья 09:00 Amsterdam — придёт автоматически)
- **Ответ:** клинический нарратив без top-N: что точно спайкает, что точно нет, эксперименты на эту неделю при нехватке данных
